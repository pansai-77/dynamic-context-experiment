# Metadata Experiment (Experiment 2)

Experiment 2 compares two retrieval methods on the same question set, corpus, embedding model, LLM, and Query-Aware handling:

| Condition | Method | Metadata filtering |
| --- | --- | --- |
| A | Query-Aware Top-4 | none |
| B | Query-Aware + Metadata Top-4 | Router Top-2 topics → OR filter → Top-4 |

Metadata was generated by the LLM and manually validated before indexing.

## Metadata schema

Each chunk stores a flat `topics` list with 1-2 values from the controlled 17-topic vocabulary.

Formal index builds accept **format validation only**:

- valid JSON
- topics from the controlled vocabulary
- 1-2 topics, no duplicates
- fallback topic exclusivity
- retry feedback mentions format/structure errors only

Content keyword rules are **not** used in formal builds. `metadata_quality.audit_content_warnings()` only emits development warnings and never modifies `final_topics`.

## Development diagnostics

- `metadata_experiment/data/chunk_splits.json`
  - `development`: 12 diagnostic chunks used during prompt engineering only
  - `validation`: reserve unseen chunks for fixed evaluation
- `python metadata_experiment/scripts/diagnose_classification.py`

Do not treat 12/12 diagnostic pass as a build gate. Do not add per-chunk keyword rules based on diagnostic or sample results.

## Build workflow

1. Run quality sample check on a fixed seed sample excluding the 12 development chunks:

```bash
python metadata_experiment/scripts/build_index.py --quality-sample
```

2. Classify all chunks:

```bash
python metadata_experiment/scripts/build_index.py
```

3. Review `metadata_experiment/data/original_metadata.csv`, distribution warnings, and audit warnings.
4. Write the index:

```bash
python metadata_experiment/scripts/build_index.py --write-index
```

## Run experiment

```bash
python metadata_experiment/scripts/run_experiment.py
```

## Evaluation

Primary Guide metrics:

- Input Tokens
- Total Time
- Score(0-3)

Optional diagnostic columns such as Hit@4, MRR@4, Filter Accuracy, and candidate counts may appear in detailed logs, but they are not Guide-required success criteria.
