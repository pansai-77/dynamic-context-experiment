# Metadata Experiment (Experiment 2)

Experiment 2 compares two retrieval methods on the same question set, corpus, embedding model, LLM, and Query-Aware handling:

| Condition | Method | Metadata filtering |
| --- | --- | --- |
| A | Query-Aware Top-4 | none |
| B | Query-Aware + Metadata Top-4 | Router Top-1 topic → filter → Top-4 |

Metadata was generated by the LLM and manually validated before indexing.

## Metadata schema

Each chunk stores a flat `topics` list with 1 value by default (max 2 when dual labels are enabled) from the controlled **v5.1 event-only** vocabulary in `topics.py` (`TOPIC_TAXONOMY_VERSION = 2026-08-04-v5.1`).

- **22 topics total**: 20 plot events + `序言与创作背景` + `其他/未分类`
- **New in v5.1**: `叙述者见闻` for the narrator frame layer
- **Removed v4 broad labels**: `家庭生活`, `贫困生计`, `死亡苦难`, `活着信念`
- Router and OR filter use the same event vocabulary as chunk classification
- Auxiliary payload fields (`characters`, `keywords`, `importance`) are stored but **not** used for filtering

Formal index builds accept **format validation only**:

- valid JSON
- topics from the controlled vocabulary
- 1-2 topics, no duplicates
- fallback topic exclusivity

Content keyword rules are **not** used in formal builds. `metadata_quality.audit_content_warnings()` only emits development warnings.

## Model configuration

| Variable | Purpose | Default |
| --- | --- | --- |
| `LLM_MODEL` | Answer generation in experiment runs | Qwen2.5-3B 4bit |
| `CLASSIFICATION_LLM_MODEL` | Chunk classification during build | falls back to `LLM_MODEL`; recommend 7B |
| `METADATA_ROUTER_TOP_N` | Router topic count | `1` |
| `METADATA_ROUTER_ADAPTIVE_TOP2` | Add 2nd topic when scores are close | `false` |
| `METADATA_CLASSIFICATION_ALLOW_DUAL_TOPICS` | Keep 2 chunk labels from first pass without single-topic retry | `false` |

When dual-topic retry is disabled (default), a chunk that returns 2 labels on the first pass triggers one strict single-topic reclassification. If the retry still returns 2 labels or invalid JSON, the chunk is exported to `classification_failures.csv` for manual override.

## Build workflow

1. Optional quality sample:

```bash
python metadata_experiment/scripts/build_index.py --quality-sample
```

2. Classify all chunks (`--no-cache` recommended after taxonomy change):

```bash
python metadata_experiment/scripts/build_index.py --continue-on-failure --no-cache
```

3. Fill `metadata_experiment/data/manual_topic_overrides.csv` for failed chunks only, using exact event names:

```csv
chunk_id,topics,notes
c0090,有庆献血死亡,manual fix
```

4. Write the index:

```bash
python metadata_experiment/scripts/build_index.py --write-index --use-manual-overrides --no-cache
```

Manual overrides apply only to chunks that failed LLM classification in the current run.

Index writes are **blocked** when any single event topic covers more than 40% of chunks. Override with `--force-write-index` after review.

## Run experiment

```bash
python metadata_experiment/scripts/run_experiment.py --limit 10
```

After filling `Score(0-3)` in `detailed_results.xlsx`, regenerate the summary:

```bash
python metadata_experiment/scripts/summarise_results.py
# or specify a run directory:
python metadata_experiment/scripts/summarise_results.py --run-dir 20260804_211643
```

## Evaluation

Primary Guide metrics: Input Tokens, Total Time, Score(0-3).

Index manifests store `topic_taxonomy_version` and `classification_prompt_version`. Stale indexes are rejected at experiment start.
